# AGENTS.md

Working instructions for this repo. Trust executable config over prose.

## Repo shape

- npm-workspace monorepo: `packages/core`, `packages/collector`, `packages/dashboard`. All ESM.
- `@election-night/core` compiles to `dist/` and must be built before the collector, server or dashboard dev mode can import it. Root `prepare` runs `npm run build:core`.
- Collector and dashboard server run TypeScript directly via `tsx`.
- `packages/dashboard` is a Vite React app plus its own Node Socket.io server in `server/`.

## Quick commands

```bash
npm run build:core     # required before most other commands
npm run dev            # Socket.io server + Vite
npm run start:collector
npm run start:server
npm run start:mock     # mock XML feed; --year 2020|2023|2026, --auto-step 15000, --stage early|mid|late|full
npm run build:mock-data # regenerate the real-result fixture the mock replays
npm run clear          # truncate SQLite and delete JSON caches
npm run log:webhooks   # local receiver on 3458
npm run lint           # eslint packages/
npm run typecheck      # core + collector, then dashboard and server
npm test               # vitest (watch); use npx vitest run in automation
npm run fmt            # prettier --write .
```

Point the collector at the mock with `XML_FEED_BASE_URL=http://localhost:3457/ POLL_INTERVAL_MS=15000 npm run start:collector`.

## Where things live

**Core (`packages/core/src`)** — no DOM, no filesystem, no barrel `index.ts`; consumers import the module path (`@election-night/core/types`, `/seat-probability`, ...).

- `types.ts` — shared types and the async, self-fetching `ElectionSource` contract. Custom sources must set `party` on every candidate vote.
- `election-results-service.ts` — historical cycles fetched lazily, single-flight, immutable; unserviceable years return `null`, never another cycle's data; failed years back off.
- `reducers.ts` — `buildResultsPayload` is the whole reduction, shared by live and historical paths.
- `count-summary.ts` — one `CountSummary` separating counted facts, contributing-place and in-seat coverage, nullable ordinary/specials estimates, and a phase (`counting`/`preliminary-complete`/`official`/`unknown`). All progress surfaces read it.
- `seat-probability.ts` — `computeSeatChance` (`waiting`/`counting`/`complete`), `probability` including specials, `countProbability` count-only, `isCountComplete`, `CYCLE_CONSTANTS` per cycle.
- `notional-baseline.ts` — baseline lookups (`priorForSeat`, `enrolmentForSeat`, `tauFor`, `chanceLookupFor`) read no files, so the browser can import them.
- `electorate-names.ts`, `electorate-successions.ts` — single name normaliser and the cited rename table.
- `polls-close.ts` — per-cycle close instant and countdown phases; unknown cycles report `null`.
- `diff.ts`, `history.ts`, `tagged-cache.ts` — shared diff/event rules, history response types, and cycle-tagged cache reading.
- `sources/nz-election-xml.ts` — the only built-in source.

**Collector (`packages/collector/src`)** — own SQLite and the scrape loop.

- `index.ts` — loop, conditional polls, commit/publish, retention sweep, fatal worker handling.
- `db-worker.ts` + `db-worker-client.ts` + `db-protocol.ts` — the worker owns SQLite; one request in flight, bounded queue, per-request deadlines, worker death exits the process.
- `db.ts` + `db/schema.ts` + `drizzle/` — Drizzle schema, migrations, snapshots, latest state, outbox claims.
- `history-queries.ts`, `history-server.ts`, `health.ts` — grouped read SQL and the public `/health` + `/history/*` surface on `HEALTH_PORT`.
- `results.ts` — cycle-tagged diff cache and `buildWebhookPayloads`; announcements are built, not sent.
- `webhook-outbox.ts` — durable delivery: lease, bounded concurrency, retry/backoff, dead letters, pruning. Owns webhook count and duration metrics.
- `serve-mock.ts`, `synthetic-electorates.ts`, `mock-election-data.json` — offline feed replaying real 2020/2023/2026 candidates and results; the fixture is generated by `scripts/build-mock-election-data.mjs`, and electorate lists are asserted against the dashboard boundary manifest.
- `clear.ts`, `log-webhooks.ts`, `source-loader.ts`, `historical-results.ts`, `retention.ts`, `metrics.ts`.

**Dashboard server (`packages/dashboard/server`)** — never opens a database.

- `index.ts` — socket receipt/ack, static serving, history API; `validation.ts` + `results-envelope.ts` + `publisher.ts` reject malformed, stale, wrong-cycle or unauthorised frames.
- `history-upstream.ts` — HTTP client for the collector with a verified/cached/stale `HistoryRead<T>`; a failed refresh may serve a value only inside the stale window.
- `api.ts`, `health.ts`, `static.ts`, `feed.ts`, `metrics.ts`, `collector-watchdog.ts`.

**Dashboard app (`packages/dashboard/src`)** — editorial UI.

- `pages/` — Seats, Electorates, Candidates, Close Calls, Flipped, Parties, Trends, Feed.
- `components/ElectorateDetail.tsx` + `ElectorateCountBand.tsx` + `ElectorateResultsTable.tsx` — the seat panel; the band shows count state, never a probability.
- `components/ParliamentSeats.tsx` — chamber in conventional coalition order; draggable order, computed `winningCoalition`.
- `components/WinPercentDrawer.tsx` + `WinPercentContent.tsx` + `WinPercentFigures.tsx` — one Win % explainer drawer, opened from Seats, Close Calls, Flipped and seat panels. Content is a fixed worked example tagged `Example`, never live data.
- `components/MapControls.tsx` + `ElectorateMap.tsx` + `VotingPlaces*` — map, search, General/Māori switch and the in-seat voting-place layer.
- `hooks/useSeatChances.ts` — the single place pages obtain a seat's chance. `lib/seat-chance.ts` injects the generated baseline; `lib/history-api.ts` owns browser history queries; `lib/query-client.ts` owns the one QueryClient.
- `lib/constants.ts` — party renames, colours and fixed order all resolve through `canonicalPartyName` / `partyColor` / `splitParties`.
- `lib/electorates.ts` — boundary year selection and name matching for `public/boundaries/<year>/`.

**Scripts (`scripts/`)** — all are live generators or validators: boundaries, icons, notional baseline, special-vote shares, specials measurement/parsing, seat-probability evaluation, promo capture and `fly-validate.sh`. `docs/promo/` is the regenerable screenshot set.

## Design system

- `design.md` is the locked system (editorial/newsprint: Playfair Display, Crimson Pro, Inter, IBM Plex Mono; hairline panels; masthead red; manual light/dark toggle). Token source of truth is `packages/dashboard/src/styles/index.css`. Amend `design.md`, not individual pages.
- Light is the default; an inline script adds `dark` only when localStorage holds `election-night:theme = dark`. The OS preference is deliberately ignored.
- Install icons are generated by `scripts/generate-icons.mjs`, never hand-resized; `lib/app-icons.test.ts` checks the shipped files against `site.webmanifest`.

## Architecture notes

- **Core is built.** `packages/core` ships `dist/`; run `npm run build:core` after changing it. Root `tsconfig.json` references only core and collector; the dashboard typechecks separately.
- **Socket.io is the backbone.** Collector is the client, dashboard the server (`WS_PORT`, default 3456). `index.html` preconnects to `http://localhost:3456`.
- **Results come from the official XML feed.** Live cycle: `https://media.election.net.nz/xml/` (no year in the path). Archives: `https://archive.electionresults.govt.nz/electionresults_{YEAR}/xml/`. `ELECTION_YEAR` selects the cycle; `XML_FEED_BASE_URL` overrides only the cycle being counted.
- **A validator must travel with its body.** A fetched body is committed before its `Last-Modified` stamp advances, or a later `304` reuses stale data.
- **The latest committed state is the truth, not the last frame.** `latest_state` holds one revisioned, publication-keyed full payload per cycle; a retry reuses its key, `A -> B -> A` gets a new revision. Socket frames are revisioned and acked; delivery is at-least-once. Clients bootstrap from `/api/history/latest` on start/reconnect.
- **History is a query with freshness.** Proxy verified TTL 10s, maximum stale fallback 120s, then `503`. Mutable responses are `no-store` with `X-Election-History-*` and `X-Election-Revision`. `/ready` probes the collector; `/health` is liveness only.
- **SQLite is owned by one worker.** History reads go through it too, so a write cannot block `/health`; `better-sqlite3`, Drizzle, migrations auto-run. `RETENTION_HOURS` (default 24) plus a periodic sweep and compaction bound the file; below 5% free space the window collapses to 1h. A full volume fails loudly only through metrics.
- **The dashboard server never opens a database.** It reads `HISTORY_UPSTREAM` (loopback in the combined image) and uses Socket.io for live results.
- **History and caches are scoped to one cycle.** `?year=` override; `tagged-cache.ts` ignores a cache tagged with another cycle or an unattributable legacy array.
- **Count semantics.** A missing estimate is `null` and prints unavailable, never zero. An official result has no outstanding votes; an unvalidated `final` flag is not official. `percentVotesCast` is turnout, not counting progress; `percent_voting_places_counted` is places, not votes.
- **Probability is a versioned forecast.** `probability` prices the special vote as one more variance term, so it is at or below `countProbability` and converges on `specialsProbability`; `complete` does not claim the seat is decided. Specials per seat are scaled by `specialRatio` from `packages/core/data/special-votes-by-electorate.json`. Do not retune constants without the versioned evaluation report.
- **No browser in the collector.** Do not reintroduce Playwright/Cheerio/HTML scraping.
- **`calculateLead` resolves party from each candidate.** There is no name -> party map.
- **Boundaries are keyed by year and matched by name.** `selectBoundaryYear()` scores manifests; unreconcilable names raise a "Boundary mismatch" banner rather than drawing the wrong cycle. See `docs/2026-election-boundaries.md`.
- **Party renames are keyed by canonical name.** Party 24 is TOP in the 2023 archive and Opportunity Party in the live feed; every chip, colour and order resolves through `lib/constants.ts`.
- **Voting places describe where a booth stands, not when a vote was cast.** A seat's places may sit in another electorate; no place is registered against a Māori electorate, so those seats legitimately show no place layer. See `docs/voting-place-data.md`.
- **Polls close is per cycle.** Unknown cycles fall back to the plain clock rather than counting down to another election's date.

## Environment

Entry points import `dotenv/config`.

- Source: `ELECTION_YEAR` (default 2023), `XML_FEED_BASE_URL`, `PRIOR_ELECTION_YEAR`, `PRIOR_RESULTS=off`.
- Runtime: `POLL_INTERVAL_MS` (60s), `CONCURRENCY` (10), `FETCH_TIMEOUT_MS` (30s), `FETCH_PACING_MS` (300), `HEALTH_PORT` (3459), `LOG_LEVEL` (3=info), `WS_PORT`/`WS_URL`, `WS_RECONNECT_DELAY_MS` (2s), `DB_PATH`, `RESULTS_CACHE_PATH`, `ELECTION_SOURCE_PATH`, `COLLECTOR_ENABLED`.
- Data bounds: `RETENTION_HOURS` (24), `RETENTION_SWEEP_MS` (15m), `HISTORY_WINDOW_HOURS` (24), `HISTORY_MAX_SNAPSHOTS` (2,000).
- Delivery: `WEBHOOK_URL`, `WEBHOOK_LOG_PORT` (3458), `RESULTS_TOKEN`, `ALLOW_REMOTE_RESULTS`, `COLLECTOR_FAULT_WRITE_FILE` (rehearsal only).
- Web server: `DIST_DIR`, `CACHE_PATH`, `FEED_CACHE_PATH`, `MAX_FEED_EVENTS` (200), `CLEAR_TOKEN`, `CANONICAL_HOST`, `HISTORY_UPSTREAM`, `COLLECTOR_METRICS_URL`.
- Frontend: `VITE_WS_URL`, `VITE_ELECTION_YEAR`.
- Mock: `MOCK_PORT` (3457), `MOCK_ELECTION_YEAR` (2023).
- Observability: `APP_VERSION`, `GIT_SHA`.

A split deployment needs `ALLOW_REMOTE_RESULTS=true` **and** a matching `RESULTS_TOKEN`; the flag alone grants nothing.

## Toolchain

- ESLint ignores `**/components/ui/**`, `**/dist/**`, `**/node_modules/**`, `**/.cache/**`, `**/.data/**`; disables `no-explicit-any`, `no-empty-function`, `no-shadow` and `no-console`; unused vars warn except arguments.
- Prettier: `singleQuote: true`, `trailingComma: es5`.
- Tailwind dark mode is `class`-based.

## Testing

- Vitest runs `packages/*/src/**/*.test.{ts,tsx}`, `packages/*/server/**/*.test.ts` and `scripts/**/*.test.mjs`. `packages/dashboard/src/test/setup.ts` stubs `ResizeObserver` and `matchMedia`.
- Highest-value suites: `pipeline.test.ts` (collector -> socket -> dashboard -> SQLite), `validator-retry.test.ts` (a failed commit survives a 304), `db-worker.test.ts` (ownership, queue, death, health under load), `history-load.test.ts` (statement counts stay flat), `history-server.test.ts`/`api.test.ts` (status, headers, 503 vs 404), `webhook-outbox.test.ts` (timeout, retries, dead letters), `results-envelope.test.ts` (duplicate/older/wrong-cycle), `count-summary.test.ts`, `specials-swing.test.mjs` (column alignment, cache versioning), `app-icons.test.ts`, `electorates.test.ts` (shipped manifests), `synthetic-electorates.test.ts`.
- Do not add tests that only pin Tailwind class strings or exact copy where a behaviour, accessible role, state or computed value can be asserted instead.

## Gotchas

- **Contract assertions belong in core.** The collector re-exports no diff helpers; `packages/core/src/diff.test.ts` owns the event rules.
- **Mock prior years still come from the real archive.** Only `PRIOR_RESULTS=off` disables them. Only 2017, 2020 and 2023 archives exist.
- **The live feed is published before election night and polls conditionally.** A `304` writes nothing; an unchanged payload writes no snapshot and broadcasts nothing; a zero-vote scrape is published but never stored or used as a diff baseline. The reference-data load is non-fatal so an unpublished feed cannot kill the process.
- **Run a new cycle by bumping `ELECTION_YEAR`.** Boundaries follow the results; the mock replays either cycle with `--year`.
- **`@election-night/core` must be built** or imports fail; `better-sqlite3` needs build tools; `.data/` is created automatically and maps to `/data` in production.
- **Production serves `DIST_DIR`.** `npm run dev` runs the server and Vite together.

## Deployment

- One Fly app (`fly.toml` + `Dockerfile.app`): dashboard public on 3456, collector loopback on 3459, both from `docker/entrypoint.sh`; SQLite and caches on `/data`.
- Migrations `0003`-`0005` are additive. An image rollback does not need a schema rollback; never delete the volume or run `npm run clear` to undo a deploy.
- The collector reads a cached static XML asset reachable from datacenter egress; no proxy is needed. `Dockerfile.collector` remains for standalone use.
- PR previews use `fly.preview.toml` (no volume, `COLLECTOR_ENABLED=false`).
- CI: `checks.yml` (lint/typecheck/test) and `security.yml` gate `deploy.yml`; `preview.yml` deploys PR previews. The production dependency audit blocks on high advisories; the full audit is non-blocking while the dev-only `braces` chain under Tailwind 3 has no fixed release.
