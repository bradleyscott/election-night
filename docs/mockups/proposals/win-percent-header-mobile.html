The Win % header on a phone · four compact variants

proposal

The two-line header is right on a wide table and expensive on a phone. At 390px the second line, ⓘ How it works, is 83px wide against a 45px label, so it sets the column. In the table below it renders 109px with a 43px header; the same label with Info beneath is 78px, and a one-line header of the same label is 37px tall. The words earn their room on desktop; below sm they are what squeezes the candidate column. Three of the variants below change only the phone; the dotted rule, which was chosen, is one line at every width.

The rule that makes the difference is simple: a second line only costs width if it is longer than the label above it. Info is 35px including the mark, so the column falls back to the label and drops 31px; How it works is 83px, so the sentence becomes the column. Everything else here is a trade between keeping that word and keeping the header to one line.

Decided

The dotted rule (4). C’s second line is gone: the header is one line, the label carries a 2px dotted rule in its own ink, and in the running app the column drops from 103px to 68px with the row from 43px to 36px. The other three are kept below as the alternatives considered.

What it costs The subline is 83px, so the column is 109px. The candidate column is 123px, enough for a name on one line and no more. The table still fits 390px; the space it spends is the space a fifth column would need.

What is not wrong The words are the reason C was chosen: the header says what the click does without the reader decoding a mark. The problem is not the sentence, it is the phone.

The fix Keep the desktop, change what happens below sm. Every variant below is one button with responsive children, not a second trigger: the accessible name, the hit area and the drawer stay as they are.

The rule One line: the label wears a 2px dotted rule in its own ink. A dotted rule is the print mark for a term with more behind it; a solid rule reads as a link to another page.

Width and height 78px and 37px. In the running app the same header is 68px and 36px. No subline and no mark, so the column is the label’s own width: it buys 31px and the line, the same width as Info.

Cost No words on the phone. The dotted rule is quieter than a sentence, so the reader still has to infer that the header is a control.

Chosen · 4, the dotted label

It is the one-line variant with a grammar already in print: a dotted rule is the mark for a term with more behind it, so the header reads as a definition rather than as a link. With the mark removed it keeps the column at 68px in the running app with the row at 36px, and it gives back 31px, level with Info. It has no word on the phone; that is the trade accepted for a single line at every width.

Implemented as the label in a span with underline decoration-current decoration-dotted decoration-2 underline-offset-4. The 2px rule is in the label’s own ink, so the existing hover colour change carries it. There is no separate mark; the accessible name, the whole-cell target and the drawer are unchanged.
